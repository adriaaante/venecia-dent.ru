## Анти-спам в форме заявок и команды бота (29.07.2026)

Повод: через форму прошла SEO-рассылка («Вы можете терять клиентов…»)
с номером `+7 (799) 900-00-00` и доменом в поле «Имя». Honeypot её не
поймал — он ловит только ботов, которые заполняют все поля подряд.

**Что теперь проверяется на приёме** (`api/lead.php` + общий модуль
`api/store.php`), по порядку — от дешёвого к дорогому:

| Проверка | Что делает | Ответ спамеру |
|---|---|---|
| honeypot `company` | как раньше | `200 ok`, тихо |
| телефон | 11 цифр, код 3/4/8/9 (не 7xx = Казахстан), не «все девятки», не хвост нулей | `400 invalid_phone` |
| чёрный список | номер добавлен командой `/ban` | `200 ok`, тихо |
| контент | см. модель ниже, **блок от 3 баллов** | `200 ok`, тихо |
| частота по IP | >40 в час = поток | `200 ok`, тихо |

### ⚠️ Модель баллов: потерять пациента дороже, чем пропустить спам

Признаки разделены на два класса, и это главное правило раздела:

- **Жёсткие (+3, блокируют сами по себе)** — то, чего пациент не пишет
  в принципе: ссылка (`http`, `www.`, `t.me/`), голый домен вне почты,
  рекламный оборот из нескольких слов («коммерческое предложение»,
  «продвижение сайта», «вывести в топ» — список в `$phrases`), отправка
  формы быстрее 1,5 с, а также связка «@ник + рекламное слово».
- **Мягкие (+1, суммарно НЕ БОЛЬШЕ 2)** — косвенные приметы: рекламные
  слова, почта в тексте, ник сам по себе, комментарий длиннее 1200
  символов, имя длиннее 60 символов. Потолок ниже порога намеренно:
  **заявка без жёсткого признака не может быть отброшена молча**,
  сколько бы мягких ни совпало.

Первая версия фильтра этого не учитывала и **резала живых пациентов**:
развёрнутая заявка пожилой пациентки («я инвалид, назначили курс
лечения, можно в кредит, есть ли бесплатный осмотр») набирала 6 баллов
и пропадала. Причины: `лидов` находилось внутри «инва**лидов**», плюс
слова `курс`, `кредит`, `бесплатный`, `обучение` — всё это нормальная
лексика стоматологии. Из словаря они убраны, короткие латинские
аббревиатуры (`seo`, `crm`, `smm`) ищутся только как отдельные слова.

Почта вырезается из текста ДО поиска доменов — иначе `olga@mail.ru`
в комментарии выглядела как ссылка рекламщика и заявка терялась.

**Лимит частоты не теряет заявки.** До 12 в час — обычная доставка,
13–40 — доставляем с пометкой `⚠️` в сообщении, и только свыше 40 в час
(или 120 в сутки) отбрасываем. Пороги высокие сознательно: мобильные
операторы прячут тысячи абонентов за одним IP (CGNAT), и лимит «3 в час»
резал бы живых пациентов с телефона.

Отказ **тихий** (`{"ok":true}`) намеренно: увидев ошибку, рассыльщик
начнёт подбирать формулировки. Всё отсеянное пишется в `spam.log`
с причиной и баллами — если живая заявка не дошла, смотреть туда.

⚠️ **Ошибка телефона отдаётся явно** (`400`), а не тихо: живой человек
мог опечататься. В интерфейсе он видит «Проверьте номер телефона —
кажется, в нём опечатка», а не общую ошибку отправки.

**Тесты — `php scripts/test-antispam.php`** (62 проверки: спам ловится,
типичные заявки пациентов проходят, включая все перечисленные выше
ловушки). Меняешь словарь или пороги → прогони, иначе легко начать
резать настоящих пациентов.

**Замер времени заполнения**: `main.js` кладёт в заявку `_elapsed` —
миллисекунды с открытия страницы. Если поля нет (посетитель со старым
закэшированным JS) — не штрафуем, иначе потеряли бы живые заявки.

### Где лежит состояние

`<домашний каталог>/.leadstate-<домен>/` — **вне публичной папки**:
`blacklist.json`, `rate.json`, `sent.json`, `spam.log`. Так оно
недоступно по HTTP и **переживает выкатку**: `deploy.sh` синхронизирует
репо через `rsync --delete`, и всё, созданное внутри `~/www/<домен>/`,
было бы стёрто. Путь переопределяется константой `LEAD_STATE_DIR`.

### Команды в группе заявок

Работают через `api/tg-webhook.php`. Бот должен быть **администратором
группы с правом «Удаление сообщений»**.

| Команда | Что делает |
|---|---|
| `/delete2`, `/delete 2`, `/deleted2` | удалить 2 последних сообщения **у всех** |
| `/ban +7 999 123-45-67` | заявки с номера больше не приходят |
| `/ban` ответом на заявку | номер берётся из самой заявки |
| `/unban <номер>` | вернуть номер |
| `/banlist` | показать список |
| `/help` | подсказка |

`/delete N` идёт назад по id сообщений от самой команды, поэтому удаляет
именно последние сообщения, чьи бы они ни были. ⚠️ **Telegram не даёт
боту удалять сообщения старше 48 часов** — это ограничение API, обойти
нельзя; при частичном удалении бот сам пишет, сколько получилось.

### Подключение webhook (один раз на сайт)

1. В `api/config.php` на сервере добавить секрет:
   `define('TELEGRAM_WEBHOOK_SECRET', '<openssl rand -hex 24>');`
   Он же защищает эндпоинт: Telegram шлёт его в заголовке, мы сверяем,
   чужой запрос отбрасывается с 403.
2. Выкатить сайт (`~/<ярлык>.sh`).
3. Зарегистрировать адрес:
   ```
   curl -s "https://api.telegram.org/bot<ТОКЕН>/setWebhook" \
        -d "url=https://venecia-dent.ru/api/tg-webhook.php" \
        -d "secret_token=<тот же секрет>" \
        -d "allowed_updates=[\"message\"]"
   ```
4. Сделать бота админом группы с правом удалять сообщения.
5. Проверить: написать `/help` в группе.

Необязательно: `TELEGRAM_ADMIN_IDS` в конфиге сузит команды до
конкретных людей (id узнать у `@userinfobot`).

Разработка — на сессионной ветке (см. инструкции сессии), пуш
`git push -u origin <ветка>`. Ветка **`main` создана 2026-07-28 по
указанию владельца** и обновляется фастфорвардом вместе с
**`claude/venetia-dental-website-vr6cb6`** (это дефолтная ветка репо —
именно её тянет `git pull` в deploy.sh на сервере; не забывать пушить
в неё, иначе правка не доедет до прода). Без нового явного разрешения
владельца в main/дефолтную ветку не пушить. PR не создавать.

## Что НЕ делать без явной просьбы

- Не выдумывать отзывы/рейтинги/врачей/реквизиты.
- Не упоминать КТ/томографию и детскую стоматологию — в клинике их НЕТ
  (владелец, 2026-07-24). Не упоминать прочее конкретное оборудование
  (микроскоп, марки сканеров), пока владелец не подтвердил оснащение.
  ТРГ+ОПТГ в прайсе оставлены — при подтверждении оснащения проверить.
- Не писать слово «премиум» в текстах сайта.
- Не пушить только в фичевую ветку — забыть про `main` и дефолтную
  `claude/venetia-dental-website-vr6cb6` = правка не доедет до прода
  (см. «Workflow пушей»).
